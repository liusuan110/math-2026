# 模拟赛（全真演练）

> 工具齐全 ≠ 能拿奖。**省一和省二三最大的差距是「这支队伍有没有被 72 小时实战训练过」。**
> 这个目录就是用来逼自己打满全流程的。

## 为什么必须模拟

赛时真正翻车的从来不是"不会某个模型"，而是：分工乱、代码临场跑不通、最后一天才动笔写论文、
提交时才发现 PDF 超 20MB / 电子版忘删承诺书 / MD5 流程没演练过。这些**只能靠模拟暴露**。

## 怎么打一次模拟赛

1. **选题**：从 [`../past-problems/`](../past-problems/) 里挑一年真题（推荐先 2023C、2024C、2024B）。
2. **全真 72 小时**：周四晚到周日晚，按 [备赛指南 §6 三天节奏](../docs/备赛指南.md) 走，手机静音、不查答案。
3. **强制走完提交流程**：按 [`提交checklist.md`](提交checklist.md) 一项项打勾，**包括 MD5、压缩、≤20MB 检查**。哪怕不真上传，也要把成品文件凑齐。
4. **结束后立即复盘**：用 [`复盘模板.md`](复盘模板.md) 趁热写，第二天就忘了。

## 目录约定

每次模拟新建一个目录，命名 `年-月-第N次_题号`，例如：

```
mock-contests/
├── 2026-07-第1次_2023C/
│   ├── 论文.pdf            # 最终成品（走完提交流程的那一版）
│   ├── code/               # 当次代码
│   ├── figures/            # 当次图
│   └── 复盘.md             # 复制 复盘模板.md 填写
└── 2026-08-第2次_2024B/
```

## 建议节奏（赛前 2 个月）

| 时间 | 目标 |
|------|------|
| **7 月中** | 第 1 次模拟：重点跑通「分工 + 工具链 + 提交流程」，结果差没关系 |
| **8 月初** | 第 2 次模拟：换题型（上次 C 就这次 B/A），重点提速、提升完整度 |
| **8 月底** | 第 3 次模拟：全力按拿奖标准打，摘要和排版务必打磨到位 |

> 至少 2 次、最好 3 次。每次复盘的"下次改进 3 条"要在下一次开赛前贴在桌上。
